# Хау мач

Пет-проект для портфолио: веб-сервис, который собирает электронные чеки с почты пользователя, раскладывает покупки по товарам (с помощью LLM) и показывает аналитику трат и личную инфляцию. Free + подписка Pro (ЮKassa, тестовый режим).

## Где что лежит

- `docs/TZ.md` — техническое задание: требования, модель данных, API, этапы с чекбоксами. Источник правды по объёму работ. Живая версия: https://claude.ai/code/artifact/9b2534db-46f6-4ba9-bd1f-0a2631267317
- `docs/design/` — копии макетов и таблица экранов. Живой холст: https://claude.ai/artifact/45EA5FnoULmEEaDVRaRxKK
- `docs/brand/` — логотип: знак «хм» (х-ау + м-ач) в форме чека с зубчатым краем, надпись «хау» + «мач» (акцентным цветом).

## Структура кода

- `apps/web` — React + MUI. Экраны в `src/features/<раздел>/`, тема в `src/theme/hcTheme.ts`, клиент API в `src/api/hcApi.ts`.
- `apps/api` — Fastify. `buildApp()` в `src/app.ts` (тесты через `app.inject`), маршруты в `src/routes/`, префикс `/api/v1`.
- `apps/worker` — воркеры BullMQ.
- `packages/db` — схема Prisma (`prisma/schema.prisma`), миграции, клиент `createPrismaClient()`, сид категорий. Клиент генерируется в `generated/` (не в git).
- `packages/mail` — работа с почтой на сервере: IMAP только на чтение, белый список отправителей чеков, шифрование паролей приложений (AES-256-GCM).
- `packages/llm` — интерфейс `LlmProvider` и провайдер Claude через Claude Code CLI (по подписке, без API-ключа).
- `packages/shared` — общее для фронта и бэка: Zod-схемы ответов API, деньги (`formatRub`), категории, тарифы (`can()`), имена очередей. Экспортирует исходники TS напрямую.

## Команды

- `pnpm dev` — фронтенд (http://localhost:5173) + API (:3000); `pnpm dev:worker` — воркеры (нужен Redis): синхронизация почты раз в 15 минут.
- `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build`, `pnpm format`.
- `docker compose up -d` — PostgreSQL и Redis. `pnpm db:migrate` — новая миграция (после правки схемы), `pnpm db:seed` — справочник категорий, `pnpm db:studio` — просмотр базы, `pnpm db:seed:admin` — локальный тестовый пользователь admin / admin.
- `docker compose --profile test up -d` — тестовый IMAP-сервер (Dovecot); с ним `IMAP_TEST_PORT=31993 pnpm test` прогоняет и интеграционные тесты почты.

## Соглашения

- Префикс `HC` у глобальных сущностей: константы `HC_CATEGORIES`, `HC_QUEUES`, классы `HCApiError`, синглтоны и объекты `hcTheme`, `hcApi`, `hcColors`. Обычные компоненты, функции и локальные переменные — без префикса.
- Комментарии и тексты интерфейса — на русском. Комментарий объясняет «почему», а не пересказывает код.
- TypeScript 6 (не 7): typescript-eslint пока не поддерживает TS 7.
- Prisma закреплена на 7.10.0: метка `latest` в npm указывает на 8.0 RC. `prisma migrate dev` в 7.x не генерирует клиент сам — используйте `pnpm db:migrate` (он делает и то и другое).
- Тесты API ходят в настоящую базу из `DATABASE_URL`; тестовые пользователи создаются в домене `test.how-much.local` (у воркера — `worker.test.how-much.local`, пакеты тестируются параллельно) и удаляются после тестов.

## Решения, которые уже приняты

- Стек: React + Vite + TypeScript + MUI (Material UI), Fastify, Prisma + PostgreSQL, Redis + BullMQ, pnpm workspaces, Docker Compose.
- Источник чеков — только почта (IMAP с паролем приложения). Банковские API и «Мои чеки онлайн» не подходят: открытых API нет, привязать карту в «Моих чеках» нельзя.
- LLM — готовые модели через интерфейс `LlmProvider`: для разработки Claude через Claude Code CLI по подписке автора, для продакшена — провайдер с API-ключом (GigaChat/YandexGPT/Claude API). Своё обучение моделей не делаем.
- Чеки из писем разбирает LLM; ответ проверяется арифметикой (сумма позиций = итог), иначе письмо уходит в «Требуют внимания».
- Суммы в копейках (integer), время в UTC.
- В интерфейсе только настоящие данные и работающие кнопки: никаких демо-данных и заглушек. Раздела нет в меню, пока нет его экрана.
- Ключ `MAIL_ENCRYPTION_KEY` (32 байта в base64) — только в `.env`, в git не попадает.
- Windows: приложение Claude — MSIX-пакет, его `claude.exe` для обычных процессов лежит в `%LOCALAPPDATA%PackagesClaude_*LocalCacheRoamingClaudeclaude-code<версия>...`; путь пишем в `CLAUDE_CLI_PATH` и обновляем после обновления приложения. Проверка: `pnpm --filter @how-much/worker try:parse <письмо.html>`.
- Дизайн: Material 3 на MUI без «пузырей»: скругления 16 px у крупных блоков и 12 px у остального (в `sx` `borderRadius: 4` = 16 px, база темы 4 px). Шрифт Onest, primary `#006C4C`, фон `#F7FAF5`, цвета категорий фиксированы (см. `docs/TZ.md`, раздел 5). Эталон — `docs/design/DashboardM3.dc.html` и `Icons.dc.html`; остальные макеты в старом стиле, перерисовывать их не планируем — новые экраны делаем сразу в коде по эталону.

## Как работаем

- Автор — веб-разработчик, общаемся на русском. LLM и нейросети для него новая тема: объяснять просто.
- Двигаемся по этапам из `docs/TZ.md`, раздел 10; отмечаем выполненные пункты там же.
- Коммиты и пуши в GitHub делаю сам, без подтверждения автора (разрешение от 2026-10-13): небольшими функциональными коммитами, пуш — по готовности версии.

## Коммиты и версии

- Один пуш = одна версия по SemVer: новая возможность — вторая цифра (0.3.0 → 0.4.0), исправление — третья (0.4.0 → 0.4.1). Версия в корневом `package.json`, git-тег `vX.Y.Z`, запись в `CHANGELOG.md`.
- Коммиты на английском. Заголовок: `[область] vX.Y.Z — Что сделано` (с заглавной, в повелительном наклонении, до 72 символов), например `[web] v0.4.0 — Add sign-in and sign-up screens`.
- Области: `web` (фронтенд), `api` (сервер), `worker`, `mail`, `db`, `shared`, `ci`, `docs`; несколько — через запятую: `[api, db]`.
- Тело коммита — список изменений на английском, по одному пункту на строку.
- Если в пуше несколько коммитов, версию в заголовке ставим только последнему; остальные — `[область] Что сделано`.
